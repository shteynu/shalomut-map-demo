## P0 — до следующего деплоя

### Слайс A1 — авто-триггер AI должен переживать serverless

**Проблема.** [`submit/route.ts:72`](../src/app/api/survey/[shareCode]/submit/route.ts)
запускает `void (async () => …)()` уже после формирования ответа. На Vercel
инвокация завершается по возврату `Response`, поэтому фоновая задача с
`fetch` и таймаутом до 30 с может быть убита до отправки вебхука. Локальный
тест этого не ловит: процесс живёт дальше, а тест ждёт `setTimeout(50)`.

**Объём.**
- Перевести фоновую отправку на `after()` из `next/server` (Next 16) — он
  явно продлевает инвокацию после ответа.
- Заменить `findResponsesByRoundId(...).length` на
  `surveyRepo.getResponseCount(round.id)`.
- В `trigger-ai/route.ts` удалить неиспользуемый импорт
  `createSharedSecretHeaders` и вернуть в ответе `202` тот же
  `webhookPayload`, который реально отправлен (сейчас `timestamp`
  пересобирается заново) — либо убрать поле из ответа.
- Не логировать respondent-данные в `console.error` фонового блока.

**Критерии приёмки.** Ответ респонденту по-прежнему `200` и не ждёт AI;
вебхук уходит гарантированно в рамках продлённой инвокации; повторная
отправка не тянет все ответы раунда из БД.

**Проверка.** `src/app/api/__tests__/submit-auto-trigger.test.ts` расширить
кейсом «ответ возвращён до завершения триггера»; `npm test`, `npm run lint`,
`npm run build`; после деплоя — один контролируемый submit на выбранном раунде
и проверка Vercel-логов на исходящий POST (требует bounded approval, см.
approval gates).

### Слайс A2 — довести «дефолт порога = 1» до кода или откатить формулировку

**Проблема.** `.agents/skills/shalomut-map/SKILL.md` и коммит `71dfcef`
объявляют дефолт `1`, но в коде дефолт остался `10`:
[`setup-form.tsx:42`](../src/components/round/setup-form.tsx) (`?? 10`),
[`schema.prisma:30`](../prisma/schema.prisma) (`@default(10)`),
[`backend.ts:51`](../src/lib/types/backend.ts) (комментарий),
Python `mcp_types.py:68` и `settings.privacy_threshold` (живой `/health`
отдаёт `10`). Минимум опущен до `1`, дефолт — нет.

**Продуктовое решение (нужно от владельца).** Один из двух вариантов:

- **Вариант 1 — дефолт действительно `1`:** правки во всех пяти местах.
  Изменение `@default` в Prisma — это миграция, значит нужен подтверждённый
  environment и rollback/PITR path. Для существующих строк дефолт не
  применяется задним числом, поэтому миграция влияет только на новые раунды.
- **Вариант 2 — дефолт остаётся `10`, минимум `1`:** вернуть в `SKILL.md`
  формулировку «настраиваемый, по умолчанию 10, минимум 1» и поправить
  сообщение коммита в `PROGRESS.md`, чтобы документация не расходилась с кодом.

**Отдельно зафиксировать риск.** При пороге `1` разблокированный дашборд
показывает `questionAggregates` с `responseCount: 1`, то есть ответ конкретного
человека, и он же уходит в промпт AI. Тексты `PrivacyTooltip` и
`SetupForm` («ברמה מצרפית») в этом режиме обещают больше, чем даёт система, —
скорректировать copy для порогов ниже разумного минимума либо показывать
предупреждение при выборе порога `< 5`.

**Критерии приёмки.** Код, Prisma, Python и `SKILL.md` называют один и тот же
дефолт; UI предупреждает о деанонимизации при низком пороге; тесты покрывают
границу `0` (отклонено) и `1` (принято).

**Проверка.** `src/lib/__tests__/survey-definition.test.ts`,
`src/app/api/__tests__/api.test.ts`, `npm test`, `npm run lint`,
`npm run build`; при варианте 1 — `npx prisma validate`, `npx prisma generate`
и миграция строго по approval gate.

### Слайс A3 — регенерация инсайтов и защита от гонки

**Проблема.** Условие `if (!existingInsights)` даёт ровно одну генерацию за всё
время жизни раунда: ответы после первой сработавшей отправки анализ не
обновляют, а UI-кнопки ручного перезапуска нет — `trigger-ai` не вызывается ни
из одного компонента. При пороге `1` дашборд навсегда останется анализом
одного респондента. Проверка «есть ли инсайты» и отправка вебхука не атомарны,
поэтому параллельные отправки дают несколько вебхуков на один раунд.

**Объём.**
- Продуктовое правило регенерации: например, перегенерировать при достижении
  порога и далее не чаще одного раза в N новых ответов или по кнопке
  менеджера; зафиксировать выбранное правило в `docs/source-of-truth.md`.
- Кнопка ручного запуска анализа на `/round` с состояниями loading/ошибки
  (эндпоинт `POST /api/rounds/{roundId}/trigger-ai` уже существует и
  авторизуется через `authorizeManagerRound`).
- Идемпотентность: хранить `aiInsightsUpdatedAt` / отметку «генерация
  запущена» и не отправлять повторный вебхук, пока предыдущий не завершился
  или не истёк таймаут.

**Критерии приёмки.** Дашборд отражает актуальное число ответов; параллельные
отправки не порождают более одного вебхука; менеджер может перезапустить
анализ вручную; локальный и privacy-locked путь не вызывают провайдер.

**Проверка.** Тесты на идемпотентность и на регенерацию в
`submit-auto-trigger.test.ts` и `api.test.ts`; `npm test`; browser smoke `/round`.
