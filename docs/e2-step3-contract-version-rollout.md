Операционный runbook для шага 3 плана E2
([ai-insights-depth-plan-2026-07-27.md](ai-insights-depth-plan-2026-07-27.md),
раздел «E2 — порядок выката»), пункт 2 в «Next Up»

задеплоен на Render, `/health` прочитан.

## Результат

Шаг 3 выполнен 2026-07-29. `AI_ANALYTICS_CONTRACT_VERSION` заведён в Production
и в Preview, Production передеплоен, алиас переехал:

- `npx vercel env ls` после работы: две строки `AI_ANALYTICS_CONTRACT_VERSION`,
  Production и Preview.
- `npx vercel inspect https://shalomut-map-demo.vercel.app` →
  `shalomut-map-demo-1t7fim7ss`, `target production`, `● Ready`, алиасы
  `shalomut-map-demo.vercel.app` и `…-git-main-…` на нём. Деплой создан позже
  правки окружения, то есть держит новое значение.

**Чего этот шаг не доказал: само значение.** Переменная имеет тип Sensitive —
`vercel env pull` возвращает `AI_ANALYTICS_CONTRACT_VERSION="[SENSITIVE]"`, и
дашборд её тоже не показывает. Прочитать записанное нельзя ни до, ни после.
Доказательство, что Core действительно производит `5.0`, — только поведенческое,
см. «Как доказать результат» ниже; на 2026-07-29 оно не получено, потому что в
базе нет ни одного раунда.

Побочно установлено и опровергает прежнюю запись: **в Preview переменной не было
никогда.** `env ls` до работы показал её только в Production (создана за 20 часов
до, то есть вместе с мержем PR #13), а `env rm … preview` ответил
`Environment Variable was not found`. Значит Preview до 2026-07-29 производил
`3.0`, а не `4.0`. Старое значение Production так и осталось непрочитанным и
теперь неустановимо — оно удалено до того, как выяснилось, что тип Sensitive
делает `pull` бесполезным.

## Что нужно знать до выполнения

### Переменная читается в рантайме, но Vercel применяет её только к новым деплоям

[`getProducedAnalyticsContractVersion()`](../src/lib/services/analytics.service.ts)
читает `process.env` на каждом вызове, так что билд её не инлайнит. Но уже
выкаченный деплой держит свой снимок окружения, и правку подхватит только новая
сборка. Redeploy — не опциональный хвост, а часть шага.

### Опечатка тихо откатывает на `3.0`, а не оставляет как есть

Функция признаёт ровно две строки, всё остальное — включая `5`, `v5.0` и пустое
значение — даёт `3.0`:

```ts
if (version === '5.0') return '5.0';
if (version === '4.0') return '4.0';
return '3.0';
```

Ошибки при этом не будет: раунды просто поедут по старому контракту. `.trim()`
применяется, поэтому перевод строки в конце значения безопасен. В сочетании с
типом Sensitive это значит, что опечатку нельзя ни увидеть, ни вычитать — только
поймать по поведению.

## Чеклист команд

CLI локально не установлен, поэтому всё через `npx` (первый запуск ставит
`vercel@58.1.0`). Проект уже слинкован: `.vercel/project.json` →
`shalomut-map-demo`, скоуп `shteynumaks-1343s-projects`.

### 1. Аутентификация и текущее состояние (read-only)

```bash
npx vercel whoami
```

```bash
npx vercel env ls
```

`env ls` показывает, в каких окружениях ключ заведён, и дату создания — но не
значение. Для Sensitive-переменных это единственное, что вообще доступно на
чтение, поэтому шага «прочитать текущее значение» здесь нет: он невыполним.

### 2. Записать значение в Production

У `vercel env` нет update — только remove и add. Если `env ls` ключа не показал,
`rm` пропускается: команда завершится ошибкой `Environment Variable was not
found`, и это не признак проблемы.

```bash
npx vercel env rm AI_ANALYTICS_CONTRACT_VERSION production --yes
```

```bash
printf '5.0' | npx vercel env add AI_ANALYTICS_CONTRACT_VERSION production
```

Пайп здесь работает потому, что для Production у `env add` ровно один вопрос —
значение.

### 3. Записать значение в Preview — интерактивно, без пайпа

```bash
npx vercel env add AI_ANALYTICS_CONTRACT_VERSION preview
```

Ввести `5.0`, затем на вопрос `? Git branch?` нажать Enter — пустой ответ
применяет переменную ко всем preview-веткам.

Пайп для Preview не годится и молча ничего не сделает: `printf` закрывает stdin
после значения, вопрос про ветку остаётся без ответа, и команда обрывается без
`✓ Added`. Именно так это и произошло 2026-07-29 при первом прогоне.

### 4. Убедиться, что обе строки на месте

```bash
npx vercel env ls
```

Ожидается две строки `AI_ANALYTICS_CONTRACT_VERSION` — Production и Preview — со
свежей датой создания. Проверить значение на этом шаге нельзя, см. «Результат».

### 5. Передеплоить Production

Сначала узнать, какой деплой держит алиас — это не обязательно самый свежий в
`vercel ls`:

```bash
npx vercel inspect https://shalomut-map-demo.vercel.app
```

Взять `url` из вывода и передеплоить именно его, подставив реальный адрес вместо
приведённого здесь:

```bash
npx vercel redeploy https://shalomut-map-demo-1t7fim7ss-shteynumaks-1343s-projects.vercel.app
```

Именно `redeploy`, а не `npx vercel --prod`: второй собирает локальное рабочее
дерево, а не `main`. `redeploy` пересобирает тот же исходный коммит, что и
целевой деплой, — поэтому целевым должен быть деплой с `main`. В дашборде
эквивалент — Deployments → текущий Production → ⋯ → Redeploy.

### 6. Убедиться, что алиас переехал

```bash
npx vercel inspect https://shalomut-map-demo.vercel.app
```

В выводе должен быть новый `id`, `created` позже правки окружения и список
`Aliases` с `shalomut-map-demo.vercel.app`.

## Как доказать результат, не трогая квоту

Доказательство `5.0` не требует живого раунда и не упирается в квоту Gemini.
[`/api/mcp`](../src/app/api/mcp/route.ts) отдаёт `contractVersion` прямо в
payload, и отдаёт его в том числе для locked-раунда — провайдер при этом не
зовётся вообще. То есть шаг 3 проверяется отдельно от шага 4.

Нужен `MCP_SHARED_SECRET` (есть в `.env.vercel-production.local`) и любой
существующий `roundId`; вызов — JSON-RPC `tools/call` с именем
`get_round_analytics`. Заголовок `Authorization: Bearer <secret>`, сравнение
строки точное
([`shared-secret.ts`](../src/lib/server/shared-secret.ts)).

Загвоздка одна: база пуста с 2026-07-28 — `0` организаций, `0` раундов. Раунда
для проверки нет, и до него нужен пункт 4 в «Next Up» — вход менеджером и первая
настройка. Поэтому шаг 3 выкачен, но не доказан: до первого раунда нельзя
отличить записанное `5.0` от опечатки, дающей `3.0`.

## Что этот шаг не закрывает

Шаг 4 (живой раунд и `inspect-ai-provenance` на нём) остаётся открытым и
упирается в другое. Семафор `LLM_MAX_CONCURRENT_REQUESTS=2`, задеплоенный
2026-07-29, снял класс `429`, который рождался всплеском: оба LLM-узла отдавали
около 33 вызовов в `asyncio.gather`, и лимит параллельных запросов бесплатного
тира выгорал в первую секунду раунда. Квотный `429` он не трогает — раунд
по-прежнему примерно 33 вызова, и free tier отказывает по частоте независимо от
того, идут они по два или залпом. Цена такого отказа сейчас — весь раунд
целиком (`provider_unavailable`).

Второе предусловие шага 4, записанное в «Next Up»: убедиться, что в дашборде
Render не задан явно `MAX_TOKENS_PER_DIMENSION` — ни `render.yaml`, ни
`.env.render.local` его не задают, поэтому дефолт `2048` применится только если
переменной там нет.
