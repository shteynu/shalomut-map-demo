### Слайс 0.1 — вернуть доступ к странице входа

**Проблема.** `/login/` отдаёт `401`. При `trailingSlash: true` реальный путь —
`/login/`, а `src/middleware.ts:21` сравнивает `pathname === "/login"`, поэтому
страница не попадает в публичный bypass и упирается в Basic Auth. `/api/auth/*`
не затронуты, там `startsWith`.

**Объём.** Нормализовать pathname в middleware (срезать завершающий слэш перед
сравнением) и покрыть тестом оба варианта пути. Проверить те же сравнения в
`src/lib/server/basic-auth.ts` (`isRespondentRoute`, `isMachineAuthenticatedRoute`)
на устойчивость к слэшу.

**Критерии приёмки.** `GET /login/` и `GET /login` отдают страницу входа без
Basic Auth; менеджерские страницы по-прежнему `401`; респондентские и
machine-роуты не изменили поведение.

**Проверка.** `src/lib/server/__tests__/middleware-session.test.ts` и
`basic-auth.test.ts` с кейсами `/login`, `/login/`, `/api/auth/login/`;
`npm test`, `npm run lint`, `npm run build`; после деплоя — живой `GET /login/`.

**Блокирует.** Включение `DISABLE_BASIC_AUTH_FALLBACK` (пункт 4 в PROGRESS
Next Up): сейчас флаг редиректит на `/login`, который `308` → `/login/` → `401`,
то есть закроет вход полностью.

### Слайс 0.2 — убрать дефолтные креденшелы и дефолтный секрет сессии

**Проблема.** В Vercel не заданы `SESSION_SECRET`, `MANAGER_ADMIN_EMAIL`,
`MANAGER_ADMIN_PASSWORD`. Рантайм берёт значения из публичного репозитория:

`src/lib/auth/jwt-session-provider.ts:8` (дефолтный ключ подписи). При этом
`/api/auth/login` доступен вне Basic Auth, а валидная сессия обходит Basic-гейт
(`src/middleware.ts:34`).

**Объём.**
- Fail-closed на deployed runtime: без `SESSION_SECRET` не выдавать и не
  принимать сессии (по образцу `durable-write-guard.ts`), без
  `MANAGER_ADMIN_PASSWORD` не заводить дефолтного администратора.
- Убрать хардкод второго пользователя `manager123` или перевести его на env.
- Хранить пароль как hash, а не как сравнение открытых строк.
- Задать `SESSION_SECRET`, `MANAGER_ADMIN_EMAIL`, `MANAGER_ADMIN_PASSWORD` в
  Vercel (Production и Preview) — **требует approval пользователя**, значения
  вводит владелец проекта.

**Критерии приёмки.** На deployed runtime без секретов `/api/auth/login`
отвечает `503`, а не выдаёт сессию; с заданными секретами логин работает;
дефолтные строки из репозитория больше не дают доступа; локальная разработка без
env остаётся рабочей и явно помечена как dev-режим.

**Проверка.** Тесты в `src/lib/auth/__tests__/manager-auth-service.test.ts` и
`jwt-session-provider.test.ts` на отсутствующие секреты; unauthorized-тесты по
матрице `shalomut-verification` (auth/secrets → unauthorized, missing-secret,
organization-isolation); `npm test`, `npm run lint`, `npm run build`;

**Критерии приёмки.** Директор может создать раунд, удалить или не загружать

## Approval gates

- Задание `SESSION_SECRET`, `MANAGER_ADMIN_EMAIL`, `MANAGER_ADMIN_PASSWORD` в
  Vercel: значения вводит владелец проекта.
- Снятие Vercel alias, удаление env `PP_BASE_URL`, любые изменения deployment.
- Любая миграция БД: только после подтверждения окружения, target и
  rollback/PITR.
- Live staging E2E для контракта `4.0` и любые вызовы webhook с реальным
  провайдером.

## Как проверять (из `.agents/skills/shalomut-verification`)

- UI и компоненты: targeted-тесты, `npm run lint`, `npm run build`, browser smoke
  затронутого флоу.
- API, сервисы, репозитории: ближайшие тесты, затем `npm test` и `npm run build`.
- Опросник, scoring, privacy: survey-definition/math/API тесты плюс
  respondent и locked/ready состояния.
- AI-контракт: contract/client/view-model тесты, `npm test`, Python-тесты,
  локальный boundary-E2E.
- Auth и секреты: unauthorized, missing-secret, organization-isolation тесты и
  security-review диффа.
- В отчёте разделять `passed` / `failed` / `blocked` / `not run` и указывать
  окружение.
